### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут включать/выключать отопление в своих домах (удалённо)
- Система поддерживает только управление отоплением 

**Мониторинг температуры:**

- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс.
- Система поддерживает только вариант получения показателей температуры через запрос от сервера к датчику и только один тип датчиков.

**Общая функциональность/ удобство**

- Система поддерживает только синхронное взаимодействие с пользовательскими устройствами инициатором которого выступает система. 
- Всё управление идёт от сервера к датчику* 
- Данные о температуре также получаются через запрос от сервера к датчику*.
- Для подключения очередного датчика к системе требуется участие специалиста компании.
###### * (к датчику не совсем корректно, скорее к "Контроллеру управления отопления" или "Абонентское устройство")

### **4. Проблемы монолитного решения**
- Масштабируемость: Ограничена, так как монолит сложно масштабировать по частям.
  - Существенное увеличение количества абонентских устройств при синхронной (последовательном взаимодействии между сист и устройствами) работе системы приведет к замедлению взаимодействия пользователя и его абонентского устройства.        
- Развертывание: Требует остановки всего приложения.
  - Введение новых типов устройств потребует перезапуска и системы

####   Воспользуюсь пояснением из описания задания  
   - REST API. Он хорошо подходит для синхронного взаимодействия, когда клиенту (в данном случае — другому микросервису) нужен немедленный ответ на запрос.

#### **Использовал для решения проблемы создания таблиц в БД**  
#### 1. Останавливаем все контейнеры
```console
docker compose down
```
#### 2. Удаляем volume (ВНИМАНИЕ: все данные БД будут удалены!)
```console
docker volume rm $(docker volume ls -q | grep postgres_data)
```
#### ИЛИ если не хотите удалять volume, можно проверить что внутри:
```console
docker run -it --rm \
-v ваш_проект_postgres_data:/data \
alpine ls -la /data
```

#### 3. Запускаем с просмотром логов PostgreSQL
```console
docker compose up --build postgres
```

#### В отдельном терминале смотрим логи:
```console
docker compose logs -f postgres
```
